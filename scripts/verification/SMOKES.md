# Standing Smoke Registry — AgencyTrack

This file is a **descriptive reference**, not an enforcement mechanism. Smokes are manual and per-PR — there is no CI smoke job. Use this registry to find which smoke guards a given surface before touching it, and to decide which smokes need a re-run after a change.

Local flag-ON smokes cannot run against the flag-OFF Vercel preview; they require a local `vite preview` build with the relevant `VITE_*` flag set.

All smokes read credentials from `.env.local` (never echoed — Rule 4). Common required keys: `VERCEL_BYPASS_TOKEN`, `A11Y_AGENT_EMAIL`, `A11Y_AGENT_PASSWORD`. Role-specific smokes note additional keys inline.

> **⚠️ HARD RULE — NEVER run a mutating smoke against a FEATURE-BRANCH Vercel preview. Feature-branch previews are bound to PRODUCTION Firebase (`agencytrack-2a610`).** Vercel's staging env vars are bound to the **`staging` branch specifically**, not to the Preview *environment*, so a branch cut off `staging` builds against prod. Evidence (2026-07-26, same credentials, same minute): the staging A11Y agent gets **LOGIN-OK** on `agencytrack-git-staging-…` and **AUTH-ERROR** on `agencytrack-git-<feature>-…` — the account simply does not exist in prod. **A preview driven with PRODUCTION credentials would authenticate and write the live tenant.** This supersedes the old "authorized-domains blocks previews, so they can't reach a live backend" belief, which was the right symptom read backwards (see `docs/FOLLOW_UPS.md` § Feature-branch Vercel previews are bound to PRODUCTION Firebase). Until the operator binds staging env to the Preview environment: verify a feature branch by building `npm run build -- --mode staging`, confirming the bundle carries `agencytrack-staging` and **zero** `agencytrack-2a610`, and serving it locally. `assertLegHygiene` checks prod-cleanliness only at the END of a run — i.e. AFTER any write — so a **pre-write project guard** (see `smoke-planner-week-nav.mjs`) is the real protection; generalizing it to every mutating smoke is a banked follow-up.
>
> **HARD RULE — the sweeper is an UNCONDITIONAL prerequisite before ANY mutating smoke run OR RERUN:** `scripts/staging/sweep-nonfixture-appointments.mjs --apply` then `scripts/staging/seed-fixtures.mjs --apply`. `seed-fixtures` sweeps only week-keyed `vhfix-*` docs, so every prior smoke run's **auto-id** appointments survive it and accumulate. Stale overlaps make the conflict-badge assertions in `smoke-run9-a3-conflicts.mjs` fail on REAL overlaps (its own header notes zero-badge assertions are not valid against residue). Templates are swept by nothing — `smoke-run9-a4-templates.mjs`'s cleanup leg now deletes them all. Each mutating smoke reserves a slot band (see the map in `smoke-e3-running-late.mjs`); never re-use another smoke's asserted slot — and check the FIXTURE bands too, **including durations** (`vhfix-appt-d2a` is 22:30–23:30 on Saturday runs), not just other smokes.
>
> **Why unconditional (2026-07-25, learned the hard way):** a smoke that FAILS mid-run still leaves the bookings it already made. Those strand into the next attempt — a rerun of `smoke-run9-a3-conflicts.mjs` failed its exactly-1 card check with 'found 2' purely on residue from its own earlier failed runs, even though the code fix was correct. 'No sweep required' is never a safe call for a mutating smoke: sweep, reseed, then run. The A3 rerun passed 9/9 immediately after a sweep + reseed.
