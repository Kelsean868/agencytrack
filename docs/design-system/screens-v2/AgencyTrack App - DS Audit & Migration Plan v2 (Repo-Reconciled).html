3 · Genuinely not on the repo yet

The one real build — CRO / back-office

App.jsx has no CRO branch today (handoff §7). It needs either a new cro role + dedicated dashboard (mirroring TenantAdminDashboard) or CRO tools surfaced inside ManagerDashboard gated by canConfirmSettlements. The Delivery Register + 30-day clawback clock is the single genuinely-new surface — model it on SettlementPanel / PolicyReconciliationPanel (same table + status-pill + drawer, Firestore-backed). Mockup: AgencyTrack CRO.html.

  • Net-new CRO Delivery Register + clawback clock — new component, in-pattern.
  • Port / verify Transactional emails — server-rendered HTML in functions/email-templates/* (monday/sunday nudge, password reset). Inline-style/table layout, not React. Verify vs AgencyTrack Emails.html.
  • Port / verify Remaining Track J per-screen deltas — J2 (Agent Dashboard) is next; then the agent → manager → CRO → kiosk/meeting → system → emails order (README §10).

A few short-lived data FUs are banked but not screens: multi-branch AOM data model (blocks second-branch onboarding), and restoring the branch-scoped kiosk users-list (real names).

Per-screen definition of done (repo terms)

  • Renders inside Shell; light + dark both verified (tokens only, no new hex).
  • Loading / empty / error states present (repo treats these as required).
  • Data via the src/services/* layer with tenantId — never query Firestore from components.
  • a11y CI gate green (@axe-core/playwright, eslint-plugin-jsx-a11y): labelled controls, focus-visible rings, 44px targets, reduced-motion guards.
  • npm run lint && npm test && npm run build clean; match the mockup, then commit per-screen.
