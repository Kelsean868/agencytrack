★ The seam — how the surface earns the transition

The merge lives or dies on the handoff from needs ("how much must I earn") to production ("how I'll write it"). It's solved as one full-width teal band — the only saturated element on the surface — that restates the single output of the budget (required first-year commission) as a headline, then points forward with one line ("Now, here's how you'll write it →") and a connector glyph. Budget sits above it, allocation below, joined by a vertical rule through the band: the agent reads top-to-bottom as one sentence — your life → your number → your plan to hit it. The band is a divider that asserts the number, not a step boundary. That's the whole bet: if this reads as one honest flow, drop Step 2.

1

Worksheet → required commission, with three-level disclosure

The full rev 1–5 worksheet (34 line items · 5 groups · 3 sub-calculators) is preserved but progressively disclosed: total → 5 group subtotals → items. "Edit worksheet" toggles full edit. The required first-year commission is computed live: monthly total ×12 → PAYE gross-up (÷0.80) → less renewals.

④ Send to Playground — the seam continues

9

Send bar → confirm → "target sent" ack → onOpenTab('game-plan')

The allocator's only job is to set API targets; the Playground (a step inside the Game Plan hub) back-solves them into weekly activity. The hop matches the shipped #738 pattern exactly, so the app has one Send behaviour, not two: a brief confirm sheet names exactly which line + named-product API figures hand over (nothing posts silently) → the targets are written to the Playground key (extend PLAYGROUND_INCOME_GOAL_KEY's payload) → a "Target sent" ack offers Continue to Game Plan / Stay here. ⚠ The app has no router — navigation is tab-state: "Continue" calls onOpenTab('game-plan'), landing on the pre-filled Playground step. No breadcrumb / back-button chrome — the app's bottom-nav / sidebar is the way back. One-directional: Money Needs is the source; only Life API drives the award line. (The mock previews the destination step; in-app it's the existing Game Plan tab.)

Availability, not greying — a clutter rule

Show only what the license grants. Lines a license doesn't include are omitted, never greyed/disabled — Life shows Life + A&H; General shows General + A&H; Composite shows all. A&H shows for every class. Award status is a single positive gold tag on Life only — no lock/disabled chrome anywhere. Same honesty, far less clutter.

Conventions applied

Tokens are CSS variables only (--primary, --ink, --surface-raised, --surface-muted, --border, --gold, --success…), light + dark. Type: Satoshi body · Cabinet Grotesk (font-display) for values/headlines · JetBrains Mono for labels/numerics. Lucide icons only (inline paths). ≥44px touch targets on every control; :focus-visible rings via the primary token. Currency TTD throughout. No gradient buttons. Slider thumbs use accent-color / styled thumbs in the primary token; non-eligible lines render the thumb in --ink-muted to read "counts, but not for awards" at a glance.
