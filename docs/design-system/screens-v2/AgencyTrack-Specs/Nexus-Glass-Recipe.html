Nexus Glass · Recipe & demo

A liquid-glass tier for hero cards — tokenized, AA-guaranteed.

One tokenized recipe (not per-card art) for the hero-card tier, with separate light and dark physics. Tinted backgrounds may use soft gradients; the no-gradient-buttons rule stands. Every recipe ships an opacity floor over the named surface tokens so all ink tokens clear AA — stated below for the contrast module's deterministic glass-pair tests.

Doctrine

Glass is a surface treatment, never a content style. It applies only to the top-of-screen hero summary card on a screen (one per screen). The hard rule: a glass tint that can't clear AA with our inks gets changed — the ink never does. Backdrop-filter is GPU-heavy, so Kiosk renders opaque and prefers-reduced-transparency flattens to a precomputed solid.

P
Dark physics differ on purpose
Dark glass uses a lower base opacity (0.55 vs 0.62), a brighter tint (the #4ab5b8 dark-teal, not #01696F), and a light hairline border (white @12%) instead of a dark one — so the pane reads as lit translucent glass, not a muddy film.
G
Tinted backgrounds may gradient — buttons may not
The card background is linear-gradient(135deg, tint, transparent 70%) over the base — a soft directional tint. This is a surface; the no-gradient rule on buttons is untouched (buttons stay bg-primary).
The hard constraint · opacity floor → AA-guaranteed inks
Floor rule

The effective glass background is computed as tint over the base over the darkest named app surface. Because every app surface token is itself light (light theme) or dark (dark theme), the floor is deterministic — no arbitrary photo can breach it. Light floor = base ≥ 0.62 over {surface, surfaceSoft, surfaceMute} (all L*≥0.88). Dark floor = base ≥ 0.55 over {surface, surfaceRaised} (all L*≤0.03). The contrast module asserts ink-on-effective-bg at these floors.

Test hook

For the contrast module. Add a deterministic glassPair(tintToken, theme) test: flatten tint → base(floor) → darkestSurface to an opaque effective color, then assert every ink in {ink, ink-muted, teal, gold, success, warning, danger} ≥ 4.5:1 against it. Ratios above are computed at the floor; treat them as the spec to reproduce, and if a future tint fails, lower the tint alpha or shift its hue — never touch the ink. (Ratios stated here are design-time; the module is the source of record.)

Performance · backdrop-filter is GPU-heavy
🖥 Kiosk Mode
OPAQUE — no backdrop-filter

TV / smart-display GPUs choke on full-screen backdrop-filter across many cards, and there's nothing meaningful behind the wall display to blur. Glass tokens resolve to the precomputed solid (--glass-*-solid-*). Identical look, zero filter cost.

📽 Meeting Mode
REDUCED — blur ≤ 8px

Projector + slide motion: halve the blur, drop saturation to 100%, keep the border + shadow + tint. Enough glass to read as the same tier without the per-frame cost while advancing run-of-show.

📱 In-app (agent/manager)
FULL GLASS

One hero card per screen, scrolled over real content — the case glass is for. Full recipe. @media (prefers-reduced-transparency: reduce) flattens to the opaque solid (border + shadow retained) for users who opt out.
