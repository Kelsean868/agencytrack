Goal Setting — where a manager sets targets for their reports.

The manager-facing half of the live Goals tab. GoalsPanel is role-aware via useAuth() (no props) — a Unit / Branch / Sales Manager sets and edits targets for the people beneath them, plus the Commission Playground. This sheet applies the shipped Goals v2 grammar: the cascade with the manager's own tier highlighted, exception-first agent rows banded against their tenure floor, the recommend-vs-lock control with provenance, and the reused recommend drawer. Every token / icon / state / role mapped; both themes; mobile.

Role-aware via useAuth() · ROLE
No props — GoalsPanel reads the manager's role internally. The cascade highlights their own tier (Branch here), and the sub-tabs gate: a UM sees Agents + Unit + Self; a BM adds Branch; an SM adds SM Target. The role pill (violet, --ink-accent) names the active scope. Full matrix below.
2
Agents are exception-first · NEW
The list sorts unset → below-floor → above, so the agents who need attention surface first. Each row is banded against its tenure floor (L1 200K … L6 800K) and carries a status chip — --danger Not-set, --warning Below-floor, --success Above. One row expands to show annual → monthly → weekly breakdown.
3
Recommend-vs-lock + provenance · EXISTING grammar
Setting a target reuses the recommend-vs-lock control from the coaching flow. Recommend = a suggestion the agent confirms in Game Plan (gold banner); Lock = a floor every level below must meet. Tier goals also carry "last set by" provenance so it's clear who owns the number.
4
The reused recommend drawer · EXISTING
The same drawer built for coaching: slider + direct numeric (≥44px), the tenure floor marked on the track, cascade context, and the gold "a suggestion, not their commitment" banner. Honest about authorship — a manager recommends; the agent commits.

A coaching aid, not a commit path
The Playground turns a candidate target into commission + implied apps + award reach live, so a manager can have the "here's what 620K means for you" conversation. It never writes — only Recommend / Lock do. Reuses the loop's blended-rate + awards math; no second model.
