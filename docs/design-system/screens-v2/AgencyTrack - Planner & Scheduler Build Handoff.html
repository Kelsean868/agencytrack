1 · Trust constraints — enforce at the data layer

Four non-negotiable, locked product decisions (manager tier)

These are enforced in the mockups and must be enforced in code — at the query & security-rules layer, not just the UI. A manager query that could return an agent's individual stalled prospects must be impossible, not merely un-rendered.

  1. Per-agent stalled-pipeline ratio is aggregate only — show the number + trend; never a drill-down of named prospects. Always carries an "AGG · PRIVATE" shield marker.
  2. That ratio / anything individual is private manager↔agent — never on a kiosk, leaderboard, or TV. Public surfaces rank reconciled production, not forward bookings.
  3. A manager sees a named prospect only via an agent's explicit escalation — agent-initiated, opt-in, and reversible (the agent can withdraw anytime).
  4. Tone is coaching, not surveillance — soft-week signals read as "opportunity to coach," never "failure to flag."

Any request that conflicts with these is out of scope until product reopens the decision.

Two integrations that make it one product

Plan → report: at end of day, aggregate the day's kept appointments into the existing Daily Capture → Weekly Report schema via utils/extractFields.js — the handoff is a confirm over a pre-fill, reusing Daily Capture field components, not a new write path. Escalation: an agent-side "ask my manager" affordance (on the Prep card / churn flow) writes an escalation; the manager inbox reads it; either party withdraws. Security rules are part of the deliverable — constraints §1 live at the rules layer.
