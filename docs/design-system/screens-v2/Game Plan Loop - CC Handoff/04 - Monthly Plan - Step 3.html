Monthly Plan · Game Plan Step 3 — build annotation

The pacer — break the annual target into 12 months and track actual vs plan all year.

Step 3 of the planning loop. The Year Plan set a per-line annual API target; Monthly Plan splits it into 12 monthly targets and tracks actual production month-by-month against them, so all year the agent sees whether they're on pace and what's left this month. It reads the Year Plan as input, writes a monthly-target store, and reads actuals-by-month from submissions. Saves a draft — Review & Commit (Step 4) writes the committed plan into Goals.

Slice rule

Split, pace, save a draft — no commit. The annual target is the anchor: the 12 months always sum back to it. The agent edits monthly targets (front-load a quarter, ease a slow month); actuals-by-month are READ from submissions, never stored. Past months show actual, the current month shows partial progress + pace, future months show target only. Save writes the monthly store at status: draft — Commit is Step 4. Honest data: unset reads "Set in your plan"; no-Year-Plan and no-submissions are drawn, not error-shaped.

The anchor invariant — edits rebalance, never break the sum
Editing one month must keep Σ months = annual. The footer balance pill is the live proof (TTD 600K ✓); if an edit breaks it, the pill goes amber and Save is gated. Rebalance behavior is Decision 2 below — it drives whether edits auto-flow or the agent owns each month.
Decision 1 — granularity · total-per-month ‖ per-line-per-month
TOTAL / MOOne target per monthLEAN · DEFAULT
Stores12 numbers — targets[0..11]. The plan is one API target per month; lines aren't tracked over time.
VarianceMonth actual = total submissions that month vs the month's total target. Clean, light, reads at a glance — the on-pace story most agents want.
CostA line's monthly mix isn't planned; you see when you're behind, not which line until you drill.
PER-LINEFour targets per month
Stores12 × 4 = 48 numbers — targets[month][line]. Mirrors the Year Plan's per-line shape across time.
VariancePer-line monthly pace — richest signal, but a heavier grid and 4× the editing for the agent.
CostMore to maintain and more to get wrong; most of the year-pacing value lands at the total level already.
◧

Lean: total-per-month for plan + variance, per-line as an optional drill. Store the 12 monthly totals as the plan; the PER-LINE toggle in the header is a read-mostly drill that splits a month's bar by line using the Year Plan's line shares — not a second editable grid. This keeps the data model to 12 numbers while still answering "which line is dragging June?" on demand. If Kyron wants per-line targets (not just a drill), it's the targets[month][line] model — a deliberate weight increase, flagged here rather than assumed.

Decision 2 — default split & rebalance · what happens when the agent edits one month
ADefault split · seeded, then owned
Seed with an even 1/12 of the annual target (TTD 50K each) — the honest, explainable default. Not a weighted guess; the agent shapes it. A "reset to even" affordance always returns to the baseline.
Even baseline · 12 × TTD 50KΣ = 600K ✓
BEdit one month · agent owns each, delta shown
The agent owns each month — editing one does not silently auto-rebalance the rest. A running "vs annual" delta shows the gap; the agent closes it (or taps auto-distribute remainder to spread it across the untouched future months).
↑
Apr raised to 70K · +20K over annualΣ = 620K · −20K to place
⇆

Agent owns each month; the anchor is enforced, not auto-magicked. Editing a month never silently reshuffles the others — that erases intent. Instead the balance pill shows the live delta to the annual anchor, and Save is gated until Σ months = annual. Two assists keep it low-friction: auto-distribute remainder (spread the delta evenly across untouched future months) and reset to even. Past months are locked — you can't re-plan a month you've already produced; only current + future targets are editable.
