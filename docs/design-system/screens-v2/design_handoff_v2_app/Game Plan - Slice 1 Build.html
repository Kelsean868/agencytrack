Split call
Ship the shell + Money Needs together — don't split.

The restyle is presentation-light: the data, math, and store are the existing moneyNeedsService — Slice 1 adds a per-row freq/annualize column and a collapsed-checklist layout over output that already exists. That's a styling pass, not a re-architecture. Splitting would ship a shell with a dead Step 1, which violates the "no empty data dressed as content" rule worse than a one-PR restyle does. Recommendation: one slice. Only split if the team wants the shell chrome reviewed in isolation first — then it's shell-only PR → Money Needs restyle PR, same slice.
