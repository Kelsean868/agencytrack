The commit — review the whole plan, then write the agent's real annual target.

The final step of the planning loop and the only one that writes real data. Money Needs, Year Plan and Monthly Plan all produce drafts; Step 4 reviews the whole plan in one place and commits it — writing the agent's Personal Commitment into Goals (their real annual API target) and flipping the plan draft → committed. It's deliberately a moment, not a throwaway Save. Committing takes the hub to 4 of 4 / 100% — the trigger that un-gates the whole loop.

Slice rule

Review · confirm · commit — the one real write. No new store. The review is read-only (edits happen back in Steps 2–3); reads exactly what's in the drafts (yearPlan + monthlyPlan), no fabrication. Commit is a deliberate two-step: a summary + an explicit "Commit my plan", never a one-tap Save. On commit it atomically writes the Goals Personal Commitment and flips both plan statuses to committed — the loop is never half-committed. This is the first step to use the terminal committed / done statusToken for real.

Decision 1 — re-commit-ability · the big one · both states designed
AMENDABLERe-open & re-commitLEAN
After commitThe plan stays re-openable. The agent can amend Year / Monthly and commit a new target — plans change, and this is their own cascade layer.

After commitCommit is a once-per-period act. The plan locks — no agent self-amend until a new year rolls or a manager reset.
AffordanceDone state reads "Committed for 2026 · locked." Re-open is disabled with an honest reason + "ask your manager to reopen."

⚿ Locked for 2026 · manager reset to change
↻

Lean: allow re-commit. The Personal Commitment is the agent's own layer of the cascade — plans change through the year, and locking the agent out of their own target creates a manager-reset bottleneck for an ordinary edit. So the done state offers Re-open to amend, and re-committing always passes back through the same confirm (a new target is as deliberate as the first). Both states are drawn so it's a clean product pick — if compliance wants commitments frozen per period, the locked variant is a one-flag swap (recommitPolicy: 'open' | 'locked') with no layout change.

⚿ The commit WRITES — narrowly
✓Lean: just the annual API into the Goals Personal Commitment field.
✓The monthly shape stays in the now-committed monthlyPlan/2026 — the rest of the app reads it for pacing.
✓Status flips on both plans → committed, atomically with the Goals write.
✓Field names pinned at brief time against the live Goals schema — design targets "writes the annual API commitment."
⚑

Manager visibility — lean: purely personal, no approval gate. Committing writes the agent's own cascade layer; it doesn't request manager sign-off and isn't blocked waiting on one. The review's "no approval" note says so plainly. A manager seeing the committed number (roll-up on the branch dashboard) is a read on a different surface, not an approval step here — flagged so if Kyron wants an acknowledgement step, it's an explicit addition, not an accident of this design.
