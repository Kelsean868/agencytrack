A second look at the shipped 12-step wizard, with everything I've since learned: the daily log now captures the full field set and aggregates into the weekly draft, there's an activity-points engine + pace floors, and the goal is capture everything, easy to follow. The wizard was built for agents typing a whole week from memory on Sunday — but for anyone logging daily, that's no longer the job. Recommendations ranked below.

The reframe

The wizard's job changes the moment daily logging is on. A daily/hybrid agent arrives Sunday with activity, sales, production and hours already filled from the week's logs — so marching them through 12 entry steps re-asks for data they've given. The fix isn't a redesign of the steps; it's making the wizard aware of how the week was captured and adapting the path. Weekly-only agents keep the full entry flow — it's their one capture moment.

Recommendations — ranked
1
Mode-aware path — fast vs fullFlowDo now
Branch the wizard on loggingMode: daily/hybrid → the confirm-and-reflect fast path above; weekly-only → the full entry flow. The submission payload is identical — only the path differs.
Why now: it's the whole point of building the daily log. Without it, daily loggers do the work twice and adoption of both features suffers.
2
Show pre-fill provenanceFlowDo now
Every field filled from daily gets a ✓ from daily ×N tag (reuse the Sunday-confirm grammar). Manually-entered or unfilled fields stay plain.
Why: tells the agent what to simply confirm vs what still needs them — the core of "easy to follow." Also makes the rollup trustworthy.
3
Align vocabulary & fields with the dailyParityDo now
Make the wizard's groups/labels match the daily's exactly, and carry the audit's fields — telephone contacts, lives sold, the social breakdown, delivery & service. Today the wizard rolls "calls across 5 categories"; the daily is more granular.
Why: one mental model in both places. Mismatched labels are friction and break a clean rollup. (See the aggregator field-map spec.)
4
Bring activity points into the wizardPointsNext
The side panel shows Production API + commission but not points. Add week points vs floor to WeekSoFarPanel, the submit button, and the celebration.
Why: the daily centers points; the weekly should close the loop on the same currency, not switch to a different scoreboard at the finish line.
5
Collapse the full path: 9 entry steps → 4 phase screensFlowNext
Even weekly-only agents shouldn't tap through 12 hard steps. Group into 4 phase screens (Activity · Sales · Reflection · Goals) with collapsible sections — the same grouped-card pattern the daily proved works.
Why: 12 sequential steps is the heaviest part of the current flow; phase screens cut taps without losing structure.
6
Seed next-week goals from pace + actualsPointsNext
NumField already supports a suggested value — wire it: pre-fill WK 49 targets from the points floor + this week's actuals, agent adjusts.
Why: goal-setting is the step agents skip or fudge. A smart default makes the hardest screen a confirm too.
7
Tie the celebration to points + streakPointsLater
The submit celebration counts up API. Add the week's activity points and the daily-logging streak it continued, so the reward matches what the daily trained.
Why: consistent reward currency across the loop; reinforces daily logging at the moment of weekly payoff.
8
Honest no-daily fallbackFlowLater
If a daily/hybrid agent logged nothing this week, the fast path's confirm sections are empty — fall back to the full entry path automatically, no dead end.
Why: the fast path assumes data exists; the edge where it doesn't must degrade to the full flow gracefully.

The through-line: the daily log changed what the weekly wizard is for. It was a data-entry marathon because Sunday was the only capture point. Now that the daily carries the week, the wizard's real value is the confirm + reflect — so the top three recommendations make it stop re-asking for data and spend the agent's attention where only the weekly can: rating the week and aiming the next one. The rest brings the points currency and step-weight in line with what the daily already established. None of this breaks the weekly-only agent — it just stops penalizing the ones who logged.
