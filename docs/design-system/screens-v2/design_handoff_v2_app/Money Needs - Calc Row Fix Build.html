Money Needs · Calc-Fed Row Fix — Build annotation

Rows that fit, and a calculator button that invites the tap.

A presentation-only repair of the live MoneyNeedsPanel. The shipped expense rows pack a flexible label against fixed amount / annual / action columns in one non-wrapping line, so line names truncate (worst on mobile, where they vanish), and the sub-calculator trigger is a faint ghost-text link stranded at the far right that doesn't read as "generate my figures here." This sheet specifies the redesigned CalcFedLineRow and LineItemRow — same props, same onOpenCalc, same FloatingCalcModal, no data-model change.

The problem — three symptoms, one root cause
1Layout doesn't fit
Label · amount · annual · actions sit in one flex items-center gap-2 row that never wraps. Inside the max-w-2xl panel the fixed columns (96px + 112px + buttons) leave the label too little room; on mobile it collapses.
2Field name gets cut off
The label uses flex-1 min-w-0 truncate, so "Professional / industry expenses" and "Debt reduction (non-mortgage)" render as "Professional / industry exp…" — and to almost nothing on a phone.
3Calc button doesn't invite
The trigger is a ghost text button (text-primary text-xs hover:bg-primary/5) far right, showing "Calculate" only when empty. It's visually weak, distant from its line, and competes with Reset — agents don't realise it generates the figure.
Root cause

One over-columned, non-wrapping flex row carrying a flexible label + three-to-four fixed-width controls in a narrow container. The label and the call-to-action both lose. Fix = give the label its own width and make the calculator the primary action while a calc-fed line is empty.

What changes — annotated
1
Calc-fed line becomes a bordered card
CHANGED. Each CalcFedLineRow renders a rounded-xl border card — teal-tinted (border-primary bg-primary/5) while empty, plain (border-border bg-surface) once filled — so the "from a calculator" relationship is self-evident and the explainer paragraph can drop.
2
Label gets its own full-width row
CHANGED. The name moves to a dedicated line above the value, flex-1 min-w-0 with text-wrap:pretty and no truncate. The Calculator / Edited chip sits inline, shrink-0, top-right.
3
Empty state = one primary CTA
CHANGED. When amount === 0, render a full-width min-h-12 filled button "Build with calculator →" calling onOpenCalc(calcId). No bare input, no ghost link — nothing else to tap.
4
Filled state = value first, quiet recalc
CHANGED. With a value, the editable amount + /yr lead; the trigger demotes to an outlined ≥44px "Recalculate". Reset appears only when isOverridden, same handler as today.
5
Manual rows stack on mobile
CHANGED. LineItemRow becomes responsive: below sm the description takes its own row, then amount · frequency · annual · delete on a second row. Desktop keeps one row with a roomier label. Delete target ≥44px.
✓
Everything else stays
UNCHANGED. handleItemChange, handleResetCalcLine, onBlur save, the calcKey.split('.')[0] calc-id resolution, SubCalcLineItems, and FloatingCalcModal (centred modal ↔ mobile bottom sheet, useFocusTrap) are kept verbatim.

Component spec — the two row components
ComponentRedesigned structure
CalcFedLineRow Outer div.rounded-xl.border.p-[11px_13px] — empty ? 'border-primary bg-primary/5' : 'border-border bg-surface'.
• Row 1 (always): flex items-start gap-2 → label flex-1 min-w-0 (no truncate, text-wrap:pretty) + state chip (Calculator / Edited when isOverridden), shrink-0.
• Row 2 — empty: single w-full min-h-12 primary button "Build with calculator →" → onOpenCalc(calcId).
• Row 2 — filled: flex items-center gap-2 flex-wrap → editable amount input + /yr; then outlined ≥44px "Recalculate" → onOpenCalc(calcId); plus "Reset" (outlined, ≥44px) only when isOverridden → onReset(item.id).
LineItemRow Responsive. ≥ sm: one row — label input flex-1 min-w-0 · amount w-24 · frequency select · annual /yr · delete (≥44px).
< sm: stack — label input full-width on its own line, then a second flex row of amount · frequency (flex-1) · annual · delete. The label input never shares its line with a fixed column on mobile, so descriptions stay legible. All inputs keep h-11 (44px).
States to cover
Calc-fed · empty
amount = 0. Teal-tinted card, full-width "Build with calculator" CTA. No input, no annual figure. The one obvious action.
Calc-fed · filled (synced)
amount > 0, not overridden. Plain card, Calculator chip, value-first, outlined "Recalculate". No Reset.
Calc-fed · overridden
isOverridden. Edited gold chip; "Reset" appears beside "Recalculate" → onReset restores the calculator value.
Manual · empty / typing
isCustom. Placeholder "Description"; stacks on mobile. Add-item button unchanged. Save on blur.
↔ Responsive
Single breakpoint at Tailwind sm (640px). Calc-fed cards are width-agnostic (label wraps, controls flex-wrap); only LineItemRow needs the stack variant. Both themes inherit automatically from the existing CSS-var tokens — no per-theme work.
⌨ Accessibility
CTA & Recalculate keep aria-label "Open {label} calculator". All targets ≥44px. FloatingCalcModal's focus-trap + focus-return to the triggering button still applies — the trigger is now a real button in both states, so focus return is cleaner than the ghost link.
