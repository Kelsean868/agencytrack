## 1. The four functions

New file `src/lib/activityLedger.js`. Pure. No imports from `src/services/`, no Firestore,
no React. Every function takes state as an argument and returns a value.

**`pcBreakdown(state, day)`**

```
blocks = events on `day` whose type is PC or SC,
         that are done/kept, and not cancelled or postponed
for each block, in deterministic order:
    inside = calls on `day` whose atHour ∈ [block.startHour, block.endHour)
             AND not already claimed by an earlier block
    claim inside
    inBlocks += max(block.dials || 0, inside.length)
adhoc = calls on `day` claimed by no block
return { inBlocks, adhoc, total: inBlocks + adhoc }
```

Three things that are load-bearing, not incidental:

- **The container/contents choice is per block, never per day.** A call block is scheduled
  *capacity*; a call is the *activity*. Summing one-per-block into the same total that
  receives one-per-call sums a container with its contents.
- **A call is claimed at most once**, and block iteration order must be deterministic
  (sort by `startHour`, then by id) so overlapping blocks produce a stable result rather
  than one that depends on array order.
- **Return the composition, not just the total.** The UI row reads *"8 in blocks + 2
  ad-hoc"*, and that habit is the only reason the two monotonicity bugs were findable.

**`loggedFor(state, day)`** — the evidenced counts, per counted code.

The set of counted codes **derives from `ACTIVITY_METADATA`**. Do not port `at-tally.jsx`'s
`COUNTED` array — it is a hardcoded twin of exactly the kind P0-A removed, and it also
carries floor values, which are Phase 2.1's business and not yours. `PC` and `SC` route
through `pcBreakdown`; every other counted code is one-per-block over done/kept blocks
that are not cancelled or postponed. One fact find genuinely is one appointment.

**`declaredFor(state, day)`** — the typed counts. In this slice it is a pure read over a
`declared` input shape; **no Firestore wiring, no submission reading.** Ruling C1 maps
declared onto the existing weekly submission, but that mapping is Phase 2.1's job. Here it
must be possible to call `declaredFor` with a plain object and get a plain object back.

**`weekTotals(state, anchorDate)`** — **all seven days of a Sunday-anchored week**
(ruling C12). Take the day set from `dateHelpers`; do not restate it, and do not port
`at-tally.jsx`'s `TALLY_DAYS = WEEK_DAYS.slice(0, 6)`. There is no excluded day — an agent
who works a Saturday gets credit for it. Return per-code evidenced and declared, kept
separate. **Never blend them, and never return a single merged number**: separate columns
with stated provenance is the product, and a blended figure is a spreadsheet with a login.

## 2. Never blend, and never assume

`03-DATA-MODEL.md`'s central contract is that evidenced and declared are shown separately
with the percentage evidenced visible. Enforce that in the *shape* of the return value —
if the only way to get a total is to add two labelled fields yourself, no consumer can
accidentally blend them.

Three questions are deliberately **unresolved** and this slice must not resolve them by
implementation: what exactly makes a call "evidenced" when there is no telephony bridge;
whether a past day's evidence can change when an agent back-logs; and whether declared
figures need an author and timestamp. Because every function takes state as an argument,
all three stay open. **Do not add a default that answers one of them.** If you find
yourself needing to, STOP and report which one.

## 3. The monotonicity property test

Add `fast-check` as a devDependency. Then:

```
for any state S and any new record r:   f(S + r) >= f(S)
```

Assert it as a real property for `pcBreakdown(...).total` and for **each** counted row of
`weekTotals`. Generators must produce overlapping blocks, blocks with and without `dials`,
calls inside and outside every window, cancelled and postponed blocks, and empty days —
the per-day scoping bug only appears when a block has `dials` *and* an itemised call.

**Budget the property run explicitly.** Set `numRuns` (200 is ample) and a fixed seed for
reproducibility. Do not accept the default with unbounded generators. CI on this repo is
currently flaking at roughly one episode in two runs under contention, and this slice adds
the heaviest CPU job in the suite — an unbounded property run would turn the one gate that
exists to prove an invariant into noise. **Report the wall-clock this adds**, and if it is
more than a few seconds, say so rather than absorbing it.

Also pin the source build's verified sequence as a fixture: a `PC` block with `dials: 8`
and no ad-hoc calls totals **8**; add one ad-hoc call → **9**; add a second → **10**, with
the row label reading `"8 in blocks + 2 ad-hoc"`. And a direct regression test for the
scoping bug: with a `dials: 8` block, adding an itemised call *inside* its window must
leave the total at 8 and must never drop it to 1.

If fast-check finds a counterexample, paste the **shrunk** counterexample and the fix. Do
not paste a green run reached by narrowing the generator — that is how this bug survived
the first time.
