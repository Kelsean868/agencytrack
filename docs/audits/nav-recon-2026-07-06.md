## Summary — TIER VERDICT

> **TIER 1 (reskin) — with a contained TIER-2 residue on the mobile bottom-nav only.**

The shipped app **already IS the realization of the locked new-design nav proposal.** The design doc [`Nav & Quick Actions - 2 Options.html`](../design-system/screens-v2/Nav%20&%20Quick%20Actions%20-%202%20Options.html) ends in an explicit **"Decision locked"** (line 775): *"Pinned + groups is the default for every role… Workspace and Both stay available as opt-in choices in Profile → Preferences… Dual-context tools appear in both groups (tagged MINE / TEAM)… the quick-add menu is identical across layouts."* Every one of those decisions is **live in the codebase today**:

| Locked decision | Shipped realization |
|---|---|
| ★ Pinned + job-based groups, default all roles | `usePinnedNav` + `PINNED_SEEDS` ([navConfig.js:239](../../src/components/shell/navConfig.js)); grouped `sectionLabel` sections rendered by `groupBySection` ([Sidebar.jsx:195](../../src/components/shell/Sidebar.jsx)) |
| Workspace / Both opt-in via Profile → Preferences | `useMenuLayout` + the "Menu layout" card ([ProfileScreen.jsx:459-493](../../src/components/profile/ProfileScreen.jsx)); `getWorkspaceGroups` ([navConfig.js:307](../../src/components/shell/navConfig.js)) |
| Agents clamped to Pinned | resolver clamp + disabled radio for agents ([ProfileScreen.jsx:459-493](../../src/components/profile/ProfileScreen.jsx)) |
| Dual-context tools tagged MINE / TEAM / BOTH | `scope` chip on nav rows ([Sidebar.jsx:85-89](../../src/components/shell/Sidebar.jsx); scopes set in [navConfig.js:101,114,133](../../src/components/shell/navConfig.js)) |
| Mobile: pencil removed, center ＋ opens quick-add | `fab`/`action:'quick-add'` bottom-nav ([AgentDashboard.jsx:69](../../src/components/dashboard/AgentDashboard.jsx)); `QuickAddMenu` |
| "More" opens a full-catalog drawer | `MobileNavDrawer` from the bottom-nav More button ([MobileBottomNav.jsx:82-93](../../src/components/shell/MobileBottomNav.jsx)) |

So the **desktop sidebar nav needs only token/CSS polish** — its IA, sections, order, pinned model, workspace toggle, scope chips, and role gating already match the locked spec. The **only structural residue** is a small mobile-bottom-nav reorder (centre the FAB; fold Profile into "More"), which is Tier-2-class but confined to one array. There is **no Tier-3 signal**: no new sections, no changed role-visibility model, no changed mobile *model* (bottom-tabs + elevated centre FAB + More drawer is unchanged), no changed routing approach.

**Planner is a separate job, not a nav change** (Task 4): the `planner` slot already exists in nav as a coming-soon stub; building the Planner *screen* is a distinct net-new track.

Most item-level differences vs the mockups are the **app being AHEAD of the mockups** (Financing/Track K, Settlements, Team Plans, My WAR, Money Needs, Team Roster, Reconciliation post-date the mockups), not deltas to build.

## Task 6 — CLASSIFY (evidence)

**TIER 1 (reskin)** is the headline, because every Tier-1 criterion holds for the desktop sidebar and the mobile *model*: same sections, same items (modulo the app being ahead), same order, same role gating — only styling/icon/spacing polish remains. The nav IA the spec "prescribes" is already the deployed IA; the spec's own "Decision locked" describes the shipped code.

**Why not TIER 2 overall:** Tier-2 requires renamed/reordered/regrouped sections or items moved sidebar↔more *as the substance of the change*. Here the only such move is a **single mobile-bottom-nav reorder** (FAB slot-2→center, Profile→More) — a contained residue, not the character of the job. It is called out explicitly so it is not lost, but it does not make the whole surface a reorg.

**Why not TIER 3:** no new sections, no new destinations (Planner already stubbed), no changed role-visibility *model* (roles/gating unchanged), no changed mobile *model* (bottom-tabs+FAB+More-drawer preserved), no changed routing approach (`activeTab` switch untouched). None of the Tier-3 triggers fire.

**Rule 23 — what would move the tier:**
- **↑ to Tier 2:** if the dispatcher decides to adopt the mobile bottom-nav reorder (center FAB + Profile→More + grouped More drawer) **as part of this pass** rather than deferring it — that promotes the mobile surface to a genuine reorg.
- **↑ to Tier 3:** if the missing sales_manager / tenant_admin / platform_admin nav specs (Task 2d) turn out to prescribe **new sections or a changed role-visibility model** for those roles; or if the inspectable-later `app-shell.jsx` mockups reveal a **new global element** (e.g. a shipped command palette or a top-nav model) the app lacks. Either would introduce new destinations / changed model.
- **↓ stays firmly Tier 1:** if the dispatcher rules the mobile reorder out-of-scope (defer to a follow-up) and confirms SM/TA/PA keep today's inline nav — then the entire pass is token/CSS only.
